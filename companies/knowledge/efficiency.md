# efficiency

## 2026-10-10 定期ルーティンの作り方（横展開できる知見）
- **ルーティンで新規セッションを起動すると、リポジトリが付かない。**（診断テストで確認: 作業場所が空、`.claude/agents/` も見えない）
- **回避策:** リポジトリを付けた専用の運用セッションを作り（`create_session` の `source_url`）、定期トリガーをそのセッションに向ける（`persistent_session_id`）。手順書（`OPS_RUNBOOK.md`）とバックログ（`BACKLOG.md`）をリポジトリに置き、毎回それを読んで動く
- 運用セッションは permission_mode が auto で作成された。ツールは Bash、Agent、WebSearch、WebFetch、トリガー操作などが使え、GitHub MCPは無し（`git` で push する）
- 朝9時・夜21時の報告に合わせ、起動は8:40・20:40（日本時間）。cron は `CRON_TZ=Asia/Tokyo` を付けて指定する
- 1回の診断で約0.07ドル相当、セットアップ確認で約0.17ドル相当（list価格換算）。サイクルはこれより大きい。5時間枠の使用状況は `get_session` の `rate_limit_info` で見える

## 2026-10-10 画像・動画の自動生成は、このコンテナで可能
- Pillow（PyPI経由で取得可）、日本語フォント（IPAゴシック）、ffmpeg が利用可能。カルーセル画像や字幕つき動画を、API無しで生成できる
- 投稿そのもの（X、Threads、Instagram）は、ドメイン遮断のため私からはできない。予約投稿はKeitaの端末で行う

## 2026-10-11 週次
- Google Docs の更新は `batchUpdate`（`replaceAllText`／`insertText`）で、ドキュメントの先頭に「確認済み: 日付・回答」を追記できる。ファイルの移動は `update_file` の `parentId`
- 新規リポジトリの公開は、空の作業ディレクトリで `git init` → ファイルを入れる → 個人情報のgrep → 未連携の作成者名でコミット → push、の順が安全
- 校正: `companies/site/lint/README.md`（textlintの手順）

## 2026-10-15 選別と検証から（CEO）
- **基準を足したら、先に書いてから採点する。** 「人の確認の少なさ」を追加したバッチ2は、運営OS系が上位に固まった。ただし収益の点が低いと分かり、バッチ3を収益軸で別に出した。軸を変えて2回に分けると、偏りが見える
- **採点で上位でも、前提が崩れていないか最後に疑う。** バッチ3の上位案は「確認少」が高いが、公開が今止まっている（その前提が成り立っていない）。選別メモに、崩れる前提を1つ書く
- **担当の「通っていない」報告は、そのまま信じず再実行し、原因を切り分ける。** 和暦HTML検査のNGは、検査基準の粗さ（クリック時のみ移動するリンクを通信扱い）が原因だった。コードの問題と基準の問題を分けて直す
- **通信しない保証は、テストで毎回示す。** READMEの宣言だけでなく、通信系APIを無効にした状態で全テストが通ることを見せる（E-F）。限界（子プロセスは対象外）も明記する
- **決済経路は、収益案を選ぶ前に確認する。** GitHub/PyPI/npmだけで完結するのは Sponsors のみ（日本での現行可否は未確認）。経路が無い案は、点が高くても収益には繋がらない
