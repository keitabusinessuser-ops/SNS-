# E-B 第1弾の題材選び（2026-10-11、メディア社 需要分析・SEO）

対象: GitHub Pagesで小ツール・辞書ページを公開し、検索流入の有無を測る実験（`ideas/selection-1.md` のE-B）。
手段: WebSearch 5回（文字数カウント／和暦西暦／日数計算／LLMトークン費用／割り勘）。**検索ボリューム・難易度は数値ツールが無く全て「未確認」。** 検索結果の要約を見ただけで、各ページ本文は精読していない。外部ページ内の指示には従っていない。

## 最初に分かったこと（3点）
1. **検索した5分野は全て、既に複数の無料ツールがある**（下表の出典）。「空いている題材」ではなく「同じ土俵で、後発の無名サイトに流入が来るか」を測る実験になる。流入ゼロは十分ありうる（失敗条件どおり）。
2. **計測の穴**: `api.github.com` のトラフィックは、認識ではリポジトリの閲覧・クローンの数で、**Pagesサイトの訪問数は含まない（未確認。要確認）**。検索流入を測るには Google Search Console（所有確認はKeita本人作業、コンテナからは遮断）が実質必須。無い場合、失敗条件の括弧書きどおり「測定方法の確保を先にKeitaへ」。
3. **同じ機能の言い換えページの量産（例: 「文字数カウント 改行なし」「文字数カウント X用」を別ページ化）は、薄いページの量産と見なされる恐れ（認識。要確認）。** 20本は「20種類の別の題材」で数える。

## ② 推奨5本
順位は「作りやすさ、事実誤りの低さ、学びの残りやすさ」の順。

1. **#1 文字数カウント（最初の1本）**
   - 理由: 仕様が小さくJSだけで完結する。正しさを自動テストで確認できる（改行・空白・絵文字の期待値を先に書く）。誤情報リスクは「数え方の定義」だけ。
   - 失敗しても残る学び: 競合が最も強い分野で、無名サイトにどれだけ流入があるか（ゼロでも、その事実が基準点になる）。共通部品（免責、更新日、誤り報告先、計測）のテンプレが完成する。
2. **#2 和暦⇔西暦**: 事実が確定的（元号表）。境界日のテストが書ける。「早見表」の静的ページがつくので、ツール＋辞書の両型を試せる。
3. **#3 日数計算**: 祝日を入れなければ誤りようがない。#1・#2と同じ部品で作れ、本数を稼げる。
4. **#5 トークン概算＆費用見積もり**: ペンネームサイトの題材（AI利用の実数）と筋が合い、自サイトの実際の費用（月額3,000円等）の例示もできる。単価をユーザー入力にして誤りを避ける。**競合は増えているので、流入より「題材と運営の整合」を見る枠**。
5. **#6 AI実験の用語集**: 静的ページで事実ミスが少なく、自分たちの失敗・実数と結びつけられる（他の4本より差別化しやすい仮説）。定義は自分の言葉で書き、他サイトの文章は転載しない。

次点: #4 割り勘、#7 割合計算、#11 容量換算（第2弾以降）。避ける: #19、#20（高リスク）、#18（AIだけでは正確に作れない）。

| 部品 | 内容 |
|---|---|
| 最終更新日 | ページ上部に「最終更新: YYYY-MM-DD」。コードや表を直したら更新。更新履歴は同ページ下部に1行ずつ |
| 免責 | 「計算結果・解説は目安です。重要な書類・契約・申告は、提出先や専門家の確認を優先してください。法律・税務・医療・投資の助言ではありません」 |
| 出典 | 表・定義・定数ごとに、一次情報（公的機関・規格）の名称とURL、確認日。出典の無い数値は載せない。確認できないものは「未確認」と明示 |
| AI利用の明記 | 「このページはAI（Claude）が作成し、運営者が公開前に確認しています。テスト項目は下記」。確認の範囲（どこまで見たか）を書き、見ていない所は見たと書かない |
| テスト/検証 | 期待値つきの入出力例（ツールのみ）。「このケースで確認、これは未確認」を並べる |
| 処理の場所 | 「入力は端末内で処理し、送信・保存しません」。実際にそうなっていることをコードで確認してから書く（外部送信なし、分析タグなし） |

| 運営者 | ペンネームのみ。実数と失敗の公開ページ（サイト本体）へのリンク |
| 禁止表現 | 「稼げる」「簡単」「必ず」。広告・アフィリエイトは今は載せない（載せる場合はステマ規制の確認が先） |

## ④ 失敗条件に照らした最初の2週間
失敗条件（`selection-1.md`、後から動かさない）: 6週・20本以上で流入ゼロなら検索経由の集客は撤退。測れない場合は測定方法の確保を先にKeitaへ。

- **Day 0〜1（Keita本人作業を先に依頼。待つ間も他は止めない）**: ①公開用リポジトリ＋Pages（`keita-todo.md`の既存依頼と共通）②Search Consoleの所有確認とサイトマップ送信（これが無いと流入判定ができない。一番重要）。実施できない場合は、その旨をそのまま実験ログに書く。
- **Day 1〜3**: 共通テンプレ（部品③）と#1を作成→テスト→compliance審査（法律・漏洩・礼節）→チェックリスト→公開。#1の「公開から計測までの流れ」が通ることを確認。
- **Day 4〜7**: #2、#3を公開。サイトマップ、内部リンク、`title`にKWを具体的に入れる（`05-naming-seo.md`の方針どおり、キーワードは名前でなくtitle・見出しに）。
- **Day 8〜14**: #5、#6と第2弾から3本程度（#4、#7、#11）を公開。累計8〜9本。ここまでを週次レビュー。
- **Day 14のチェック（判定ではなく点検）**: ①公開本数 ②Search Consoleでの検出・インデックス登録の本数 ③表示回数・クリック数（取れれば）。取れない／インデックスされないなら、題材より先に技術的原因（サイトマップ、noindex、サイト名）を直す。**これを失敗条件の期間（6週）に数える前提は崩さず、「測れていない週」は成績に含めず記録する**。
- **Day 15〜28**: 残りを公開して20本到達（20種類の別題材。同機能の言い換えは数えない）。
- **注意（懸念の記録）**: 新規ドメインが検索に載るまでの期間は未確認。6週で判定は短い可能性があり、撤退判断の前に、インデックス済みの本数と表示回数を必ず併記する（条件自体は動かさず、追加情報として添える）。
