## 要点（二次情報）
| 論点 | 要点 | 備考 |
|---|---|---|
| 営業秘密（2条6項とされる） | 秘密として管理されている、事業活動に有用な技術上・営業上の情報で、公然と知られていないもの。3要件: 秘密管理性・有用性・非公知性 | 実務で争点になりやすいのは秘密管理性（解説） |
| 秘密管理性 | 保有者の秘密管理意思が管理措置で従業員等に明確に示され、認識可能であること（経産省「営業秘密管理指針」の整理、解説経由） | 指針に法的拘束力はなく、最終判断は裁判所。2025年の改訂で「従業員等」に役員・取引先が含まれると明確化との解説あり（未確認） |
| 不正取得・使用・開示 | 不正な手段での取得、不正取得した秘密の使用・開示、正当取得後の不正目的での使用・開示などが不正競争に当たりうる（一般的な枠組み。条文未確認） | 民事（差止め・損害賠償）、刑事の両面（詳細未確認） |
| 限定提供データ | 業として特定の者に提供する情報として電磁的方法により相当量蓄積・管理されている技術上・営業上の情報（秘密として管理されているものを除く）。要件: 限定提供性・相当蓄積性・電磁的管理性 | 2018年改正で導入（解説）。無償で広く公開されたオープンデータは対象外（解説）。経産省「限定提供データに関する指針」あり |
| 営業秘密との関係 | 補完的な保護類型（解説） | |

## 当社の事業との関係
| 場面 | 論点 | 対応案（仮説。専門家確認が必要） |
|---|---|---|
| 元雇用主・アルバイト先の情報 | 在職中・退職後に知った非公開の情報を、サイト・記事・ツールに使うと、営業秘密の不正使用・開示や秘密保持義務違反の論点になりうる。大学の研究室・インターンも同様 | 書かない・入れない。「公開情報か」で迷うものは使わない（漏洩ゲート）。契約・誓約書の確認はKeita |
| 取引先・店舗（C社）から預かる情報 | 預かった営業情報・顧客リストは相手の営業秘密に当たりうる。NDA・目的外利用 | 同意の範囲内で最小限。外部AIツールに入れる前に規約確認、原則入れない |
| 公開サイト『ひとりとAI』 | 運営者自身の情報は自分のもの。他人の非公開情報を載せない | 公開前チェックに「他者の非公開情報なし」を含める |
| 公開リポジトリ | 公開すると秘密管理性を失う（非公知性・秘密管理性の観点）。自社の非公開ノウハウを出すかは経営判断 | 公開するものと内部限定のものを分ける。内部限定は公開リポジトリに置かない |
| 外部ツールへのデータ入力 | 他社の営業秘密を入力すると、ツール事業者への開示・保管・学習利用の論点 | 規約の学習利用・保存を確認、原則入れない |
| 将来の「型」「ノウハウ」販売 | 自社ノウハウを秘密として管理するか、販売して公開するか。限定提供データに該当しうる商材（会員向けデータ提供）の場合は指針を確認 | 販売前に契約・規約と併せて専門家確認 |

## よくある落とし穴
- 「ネットで見つけた」「自分が覚えている」ので使ってよいと考える（出所が非公開情報の場合）
- 秘密にしたい情報を公開リポジトリ・共有リンク・誰でも見られる設定に置く（管理の意思が示されない）
- 取引先の情報を、同意範囲を超えて社内外のAIツールに入れる

## 専門家確認が必要な点
- 元雇用主・インターン先等の情報の使用可否、秘密保持の契約・規則の内容
- 預かった情報の取扱い（NDAの有無・範囲）
- 自社ノウハウの保護方針（公開と秘密のライン）
