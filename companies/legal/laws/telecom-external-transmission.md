## 要点（二次情報）
| 論点 | 要点 | 備考 |
|---|---|---|
| 義務の内容 | 対象サービスの事業者が、利用者の端末から利用者情報を外部（第三者）に送信させる場合、①送信される情報の内容 ②送信先の名称 ③利用目的 を、あらかじめ通知するか、容易に知り得る状態に置く（公表）（要約） | 実例: 「外部送信ポリシー」ページを設け、Googleアナリティクス等の送信先・情報・目的を列挙 |
| 適用除外 | 利用者の同意取得、オプトアウト措置、サービス提供に必要な情報の送信などは通知・公表の義務が外れる、とされる（要約） | 除外の細目は**未確認** |
| 送信情報の例 | IPアドレス、Cookie等の識別子、閲覧URL、流入経路、端末・ブラウザ情報（事業者の公表例） | |
| 対象 | 電気通信事業を営む者のうち、省令で列挙された電気通信役務（SNS、電子掲示板、検索、情報のオンライン提供サービス等）。利用者数による足切りは設けられなかったと評価する意見あり | 列挙の正確な範囲は**未確認** |
| 執行 | 総務大臣の業務改善命令等の仕組みがあるとの一般論 | 罰則の内容は**未確認** |

## 個人運営の小規模サイトは対象か（論点整理）
| 観点 | 整理（二次情報） | 専門家確認 |
|---|---|---|
| 電気通信事業に当たるか | 「他人の需要に応ずるために」役務を提供する事業が前提。個人が自らの知識・体験を発信するサイトは「自己の需要」とされ、総務省の案内でも、企業HP・個人ブログは電気通信事業に当たらず対象外、との整理が紹介されている | 要 |
| 境界事例 | 自己の情報に限らず、提携先・業界情報・利用者向け情報などを発信するオウンドメディアは、他人の需要に応ずる事業と見られる可能性がある、との解説あり。アフィリエイト中心、問い合わせ・投稿機能・会員機能がある場合は変わりうる | 要 |
| 『ひとりとAI』への当てはめ（仮説） | 運営者自身の体験・実数の発信で、投稿機能・会員機能・問い合わせ受付がない現状は、対象外とされる側に近い可能性。ただし**断定できない**。将来の機能追加（コメント、会員、有料販売）で再確認 | **必須** |
| note等のプラットフォーム | サービス提供者側に規律がかかりうる。利用者個人（運営者）への適用は別論点 | 要 |
| 任意の対応 | 対象外でも、アクセス解析を入れるなら、送信先・目的を公開するのは信頼面で有益。法的義務かは別 | 任意 |

## 個人情報保護法との関係
- 外部送信規律は通知・公表を求める電気通信事業法上の規律。個人関連情報の第三者提供（個人情報保護法31条とされる）は別の規律で、併せて検討される（解説）。`laws/appi.md` 参照

## 当社の事業との関係
| 場面 | 論点 | 対応案（仮説） |
|---|---|---|
| 公開サイト（アクセス解析なし） | 外部送信自体がなければ、通知・公表の論点は小さい。ただし、埋め込み（YouTube、SNSボタン、Webフォント、広告バナー、アフィリエイトのタグ）が外部送信を発生させうる | 公開前に、読み込む外部リソースの一覧を作る |
| 将来のアクセス解析 | 送信先・内容・目的の整理が必要 | `issues/site-analytics.md` |
| 将来のアフィリエイト | ASPのトラッキングタグ・Cookieが外部送信になりうる。ステマ表示（`laws/stealth-marketing.md`）とは別 | ASP規約でタグ・Cookieの記載を確認 |
| 問い合わせ受付 | 現状なし。追加時は個人情報の取得（`laws/appi.md`） | 追加前に再整理 |

## よくある落とし穴
- 対象外と決めつけて、後で機能を足してから規律に当たる
- 解析以外（広告・埋め込み・タグ）の外部送信を洗い出さない
- 送信先のプライバシーポリシーへのリンクだけで足りると考える（要件を満たす場合に限る、との意見がパブコメ資料に見られる）
- 利用目的が「サービス向上のため」など抽象的
