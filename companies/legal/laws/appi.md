## 要点（二次情報）
| 論点 | 要点 | 備考 |
|---|---|---|
| 個人情報 | 生存する個人に関する情報で、特定の個人を識別できるもの（氏名、容易に照合できる他情報との組合せ等）。個人識別符号を含む | 定義条文（2条）は未読 |
| 個人データ | 個人情報データベース等を構成する個人情報。検索できるよう体系化した名簿・顧客台帳・スプレッドシートなど | 「個人情報取扱事業者」の前提は、データベース等を事業に使っていること |
| 要配慮個人情報 | 人種、信条、病歴、犯罪歴など。取得に原則本人同意が必要、とされる（要約。条番号未確認） | 漏えい時の報告基準が厳しい（下記） |
| 個人関連情報（31条とされる） | 個人情報等に当たらない、Cookie等の端末識別子に紐づくWeb閲覧履歴など。提供先が個人データとして取得すると想定される場合、提供元は本人同意の確認が必要（要約） | アクセス解析で効きうるが、GA等が該当するか明確な結論は**確認できていない** |
| 安全管理措置（23条とされる） | 漏えい等を防ぐ組織的・人的・物理的・技術的措置。中小規模事業者向けに、ガイドラインで緩和された手法が許容される、とする解説あり | 緩和の具体内容は**未確認** |
| 第三者提供（27条とされる） | 個人データを第三者に提供するには原則あらかじめ本人同意。委託・共同利用等の例外あり | クラウド・外部ツールは「提供」か「委託」かで分かれる。個別判断 |
| 外国にある第三者への提供（28条） | 原則、移転先国名・その国の制度・提供先の措置などを本人に情報提供したうえで同意が必要。例外（同等水準の国、相当措置を講じる者）あり（要約） | 海外のAI・クラウドに個人データを入れる場面で効く |
| 生成AIへの入力 | 入力した個人データを事業者が機械学習に使える場合は「提供」と整理される、との解説あり。PPCの注意喚起（2023年6月）の原文は未読 | 学習に使われない設定、そもそも個人データを入れない運用が基本線（仮説） |
| 漏えい等の報告（26条） | 個人の権利利益を害するおそれが大きい漏えい等（要配慮個人情報、財産的被害のおそれ、不正の目的、1,000件超）は、PPCへの報告と本人通知が義務。前3類型は1件でも対象（要約） | 期限は解説により「速報3〜5日目安、確報30日（不正目的は60日）」。**数値は未確認** |

## 小規模・個人・学生への適用
| 論点 | 整理（二次情報） | 専門家確認 |
|---|---|---|
| 個人事業主・小規模事業者 | 2017年5月の全面施行で「5,000件以下は対象外」の例外は無くなった（複数の解説）。個人情報データベース等を**事業の用に供している**者は、小規模でも個人情報取扱事業者になりうる | 要 |
| 学生が運営する場合 | 学生であることによる適用除外は**確認できていない**。事業（営利・継続）として扱うかが論点。大学規則・アルバイト先との関係は別論点 | 要 |
| 個人情報を持たない場合 | 問い合わせ受付なし・アクセス解析なし・氏名等の名簿なしなら、個人情報取扱事業者としての義務が生じる場面は少ない可能性。ただし将来の解析・アフィリエイト登録で変わる | 要 |
| 2026年改正 | 報道によれば、課徴金制度の導入などを含む改正法が2026年に成立・公布（7月17日公布との報道。成立日・施行日は記事間で食い違い）。施行は公布から2年以内（報道）。**原文未確認** | 施行前に再確認 |

## 当社の事業との関係
| 場面 | 論点 | 対応案（仮説。専門家確認が必要） |
|---|---|---|
| 公開サイト『ひとりとAI』（ペンネーム運営、問い合わせ受付なし） | 現状は個人情報を集めない設計。ペンネームでも、運営者本人・第三者の情報が識別可能になる記述は別論点（名誉・プライバシー、優先4） | 個人を特定できる記述を載せない。第三者の氏名・勤務先・店舗の従業員情報を書かない |
| 将来のアクセス解析 | IPアドレス・Cookie等の送信。個人情報／個人関連情報／外部送信規律（`laws/telecom-external-transmission.md`）の整理が必要 | `issues/site-analytics.md` を参照。導入前に確認 |
| 将来のアフィリエイト | ASP登録で本人情報を提供するのは運営者自身の情報。読者の個人情報は通常取得しない（リンク経由の計測はASP側） | ASP規約・プライバシー表示を確認。Keita作業 |
| 公開リポジトリ（個人情報・機密を入れない運用） | 個人データを公開すると、第三者提供・漏えいの論点。一度公開すると履歴から消えにくい | コミット前チェック（氏名、メール、店舗の内部情報、認証情報）。誤公開時は履歴含め対応し、報告要否を専門家に確認 |
| 外部ツール（AI、クラウド、スプレッドシート等）へのデータ入力 | 個人データを入れると「提供」「委託」「外国への提供」の論点。店舗・取引先・元雇用主の情報は機密の論点も | 原則、個人データ・機密は入れない（漏洩ゲート）。入れる必要が出たら規約（学習利用・保存地）を確認し、Keitaに回す |
| C社（口コミ・店舗情報） | 口コミの投稿者名・店舗の従業員名など、個人を識別できる情報の扱い | デモは架空データ。実データは同意を得た相手のみ |

## よくある落とし穴
- 「個人だから」「少人数だから」適用されないと思い込む
- 生成AIにお客様名・メール・口コミ本文をそのまま貼る
- 公開リポジトリ・公開スプレッドシートに実データ・認証情報を置く
- Cookieを「匿名」と書いておけば足りると考える（個人関連情報・外部送信規律は別に判断される）
- 漏えいに気付いても、報告要否の判断が遅れる
