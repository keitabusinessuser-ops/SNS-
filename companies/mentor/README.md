# メンター（Keita専用）設計 v0  2026-10-30
注意: Keita個人の情報を扱う。公開禁止。公開サイト・公開リポジトリに出さない。

## Why
- MISSIONの「月50万」は、Keitaの現在地（時間・お金・スキル・制約）と、本当にやりたい生き方が言語化されていないと、選別基準が引けない
- `inputs/` の6ファイルが全部「未受領」。長い書類だと返事が止まる（keita-model.md）→ **1問ずつ・10分・一言回答**で集める
- AIがKeitaの考え方を学ぶ（達成条件2）の入力源にもなる

## What（5モジュール。順番に進める。飛ばさない）
| # | モジュール | 出すもの | 記録先 |
|---|---|---|---|
| A | 過去の棚卸し（経験・失敗・得意・消耗したこと） | 強み仮説5つ／繰り返す失敗パターン | inputs/past.md, skills.md |
| B | 現在地（時間・お金・スキル・資産・制約・数字） | 1枚の「現在地シート」 | inputs/current-businesses.md, mentor/state.md |
| C | 未来（3年後の暮らし、やりたくないこと、母親・子育て世帯支援の将来設計） | 目標の言語化（数字・期限・理由） | inputs/future.md, wanted-businesses.md |
| D | ギャップ分析（現在地→目標。足りないもの、最短の道） | 3〜5個の「次の一手」と優先順位 | mentor/state.md |
| E | 週次チェックイン（10分。毎週日曜夜） | 進捗・ズレ・来週の1手 | mentor/checkin-log.md |

## How
- 起動: 「/mentor」。モジュールA→B→C→D→E の順
- 1セッション=10〜15分、1問ずつ、選択肢か一言で答えられる形
- 毎回の終わりに「次の一手」1つ
- 目標は「何を・いくら・いつまでに・なぜ」の4点が揃うまで「言語化済み」としない
- 週次で `thinking-log/keita-model.md` を更新（Keitaの言葉・判断の癖）

## KPI
- inputs/ の受領ファイル数（0/6 → 6/6）
- 目標の言語化（4点が揃ったか）
- 週次チェックインの継続率

## リスク
- 無言が続く → 催促せず「1問だけ」で再開。負担を下げる
- AIの解釈で埋める → 空欄は「未回答」。推測は【推測】
- 個人情報 → 第三者は特定できない形。公開しない
