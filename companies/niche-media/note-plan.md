## 4枚目: 記事の型（3種）
共通: 冒頭は `positioning.md` の型（場面→結果→呼びかけ→約束→橋）。文字数と売上の相関はほぼ無いとされる（二次情報）ので、長さより具体を優先し、目安は1,500〜3,000字。末尾に「次の記事の予告」と「AIを使い、筆者が確認・編集」を入れる。

| 型 | 構成 | タイトルの型 |
|---|---|---|
| A やらかし | 場面 → 失われたもの → 原因（相手の目的を考えなかった等）→ 変えたこと → 最初の一歩 | 実際の言葉・場面を前に出す（例:「AIすぎるので、修正しましょうか」） |
| B 運営ログ | 今週やったこと → 数字（無ければ無い）→ 判断と理由 → 失敗・未遂 → 来週 | 週番号＋その週の一番の出来事 |
| C 型 | 困る場面 → 型の名前 → 使い方（ミニ版は一部）→ 実例 → 有料版の中身の予告 | 「〇〇する前の△項目」など、持ち帰れる名前 |

## 5枚目: 無料と有料の境界
- **有料ラインの位置**: 共感と結論の手前までを無料にする。有料側に置くのは、実物の型（チェックリスト全文）、実際の文面、数字の内訳
- **価格テスト**: 8週目以降。1記事1価格（500 / 1,000 / 1,500円）にして、購入率を比較する。サンプルが小さいので傾向の目安
- **売るのは有料ラインの先**: 「読み物」ではなく「持ち帰れるもの」。note内の平均価格の二次情報は、実用ノウハウ系が約1,842円、読み物系が約983円（原文未照合）
- **特商法表記が整うまで、課金しない**（専門家確認が前提）

## 7枚目: 公開の運用フロー
1. 私が記事を作り、compliance審査（法律・漏洩・礼節）を通す
2. `companies/publish-queue/note/YYYY-MM-DD-slug.md` に置く。中身: タイトル、本文（見出し・太字の指定つき）、有料ラインの位置、ハッシュタグ、見出し画像のファイル名、公開希望日、価格
3. Keitaが朝夜にコピペして公開（1本あたり数分の見込み）
4. 公開後、URLと数字（閲覧・スキ・コメント・フォロー・購入）をKeitaが私に伝える（週1回でよい）。私が `kpi.md` と事実ログに記録する
5. 週次（日曜夜）の振り返りで、型・タイトル・価格を調整する

## 8枚目: 礼節とコミュニティ
- コメントへの返信は丁寧に。自動返信はしない。誰かを貶めない
- 他のクリエイターへの言及は、事前に失礼がないか審査する。売り込みのコメントを他人の記事に付けない
- 学生コミュニティへの告知は、Keitaが判断する（会員の信頼を損なわない形で）

## 9枚目: 公開前チェックリスト（compliance）
- [ ] 企業名・個人名・特定できる情報なし（投資家・取引先・飲食店・元雇用主）
- [ ] 公開可否が未決の話題なし（恋愛・噂、解雇の経緯）
- [ ] 数字は事実ログと一致。無い数字は「無い」
- [ ] 「稼げる」と期待させる表現なし。最良事例だけを出していない
- [ ] 末尾にAI利用の明記
- [ ] 他者の文章の流用なし
