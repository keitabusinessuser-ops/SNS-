# 媒体の設計（読者・悩み・キャラ・冒頭の型）

状態: v1 / **すべて仮説**。media-seo の需要分析（`research/`）とKeitaの確認で検証し、直す。
記事を書く前に必ずこのファイルを読む。ここに合わない記事は書かない。

## 1. 誰に読んでほしいか（読者像・仮説）
AIで副業・小さな事業・仕事を進めようとしている、20代の学生や若手社会人。
AIは使えるが、AIが出したものを「そのまま人に出して大丈夫か」に自信がない人。

## 2. その人の悩み（仮説）
1. AIに頼むと、それっぽいものは出る。でも、本当に使えるのか判断できない
2. 取引先・上司・お客さんに出すのが怖い。「AIっぽい」と思われたくない
3. 楽をしたくてAIを使っているのに、確認の仕方が分からず、結局時間がかかる
4. 失敗して信用を落とすのが怖い。実は、もう一度やらかしている人もいる

## 3. 書き手（Keita）のキャラ・立ち位置（事実ベース）
- 高2から事業を始め、契約書を知らずに依頼主に飛ばれ、AIの丸投げで取引先に皮肉を言われ、就職先では基本行動ができず試用期間で解雇された
- 「できる人」ではなく、「失敗を重ねて、確認の型を作っている最中の当事者」
- 格好つけず、恥を具体的にさらす。上から教えない。同じ失敗をしている読者の隣に立つ
- 現在: 大学生。起業はしたいが、まず社会人としての基本行動を身につける段階

## 4. 読者との約束（この媒体で得られるもの）
「AIに頼んだものを、人に出す前に、同じ失敗をしないための確認の型」

## 5. 冒頭（最初の数行）の型 — 有料でも「読みたい・買いたい」にするため
1. **場面**: 読者が「それ、自分だ」と思う具体的な瞬間（できれば書き手の恥の一言から入る）
2. **結果**: その場面で何を失ったか（信用、時間、お金）
3. **読者への呼びかけ**: 読者の状況に触れる（「出す前に、少し不安になったことがあるなら」）
4. **約束**: この記事を読むと何が手に入るか（1文）
5. **橋**: 無料はここまで／続きで何が分かるか（有料記事の場合）

## 6. 避けること
- 誰が書いても同じになる一般論（「AIは便利だが確認が大事」）
- 読者の悩みに触れないまま、手順を並べること
- 書き手のキャラが見えない、無難な言い回し
- 実績の誇張。数字が無いときは「数字はまだない」と書く
- 企業名・個人名・特定できる情報
