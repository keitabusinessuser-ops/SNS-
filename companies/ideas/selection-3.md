## 判断
1. **束ねる: E-F「通信しない日本の事務ライブラリ群」** = 3-36（通信ゼロの自動証明）＋3-07（既にある和暦ツールの拡張）＋3-04/3-06/3-02（法人向けの事務ライブラリ）。ローカル完結で確認が少なく、「通信しない」を毎回テストで公開証明するのが模倣されにくい差別化（AIが作ると同質化しやすい中で、検証可能な保証を売る）。既存資産（draftgate・cite-gap・wareki）を流用できる
2. **正直な弱点（最重要）**: 50万の計算は、法人サポート 5万円×10社など。**営業をしない前提で10社を取る集客経路が無い。**GitHub/PyPI/npmだけで完結する決済は GitHub Sponsors のみ（日本での現行可否・税務は未確認、scout調べ）。つまり**収益の入口は Keita の Sponsors 登録と税務確認に依存する。**これは承認ゲート5（本人作業）かつ1（税務・専門家確認）。今は依頼しない（初収益の前提が整ってから）。それまでは「ダウンロードと問い合わせが出るか」の需要検証にとどまる
3. **普通はやらない案を1つ残す: 3-30★ 事前入金のゴール式**（欲しい人が集まってから作る）。在庫リスクなし。ただし前払いは法律論点あり、Sponsors登録の後
4. **3-26（運用ルール雛形Pro）は E-A の収益化レイヤー**として保留。実数（失敗3回の一次情報）が出てから。Keitaの体験談が材料なので、公開は確認待ち
