# アイデア創出（大量発散 → 基準 → 選別 → 小さく走らせる → 疑う）

固着を防ぐための手順。1つの案が出ても、その場で深掘りしない。必ず発散してから選ぶ。

## 手順
1. **発散**: 1回に50案以上を `ideas/YYYY-MM-DD-batch-N.md` に書く。質より量。評価しない
   - 必ず含める: 今の柱（note等）以外のチャネル・モデル、Keitaの提供情報（`inputs/`）から出た案、周りの困り事から出た案、普通はやらない案（最低5案）
2. **基準を先に書く**（下の初期基準。後から動かさない。変えるときは決定ログに理由）
3. **選別**: 各案を基準で採点し、上位5案を残す。残さなかった案の理由も記録（後で再評価できるように）
4. **走らせる**: 上位から、同時に最低3本を小さく試す（予算ゼロ、期間2〜4週）。各案に「失敗と判定する条件」を事前に書く
5. **疑う**: 週次で、走らせている案を殺す条件に照らして判定。新案の投入は常に続ける（走らせた案だけを深掘りし続けない）

## 初期基準（仮説。重み付き5点満点）
| 基準 | 重み | 問い |
|---|---|---|
| 先行有利・模倣困難 | 3 | KeitaとAIの組み合わせでしか作れない、または真似に時間がかかるか |
| AIメインで回せる | 3 | 人間の作業が「本人にしかできないこと」だけで済むか。高度な自動化の余地があるか |
| 初期費用ゼロで始められる | 2 | 課金なしで最初の検証ができるか |
| 月50万への道筋 | 2 | 単価×数量の計算が成り立つか。スケールするか |
| 法・漏洩ゲートの軽さ | 2 | 専門家確認や個人情報が不要または軽いか |
| 将来の再現性 | 2 | 「迷わず手を動かすだけ」の事業に分解できるか（対象: 母親・学生・主婦） |
| 学び・資産性 | 1 | 失敗しても記録・ナレッジ・資産が残るか |

## 失敗条件の書き方（例）
「2週間・無料で10回試して、反応（返信・購入・保存）が0なら止める」のように、数と期限で書く。

## 記録
走らせた案・殺した案は、`knowledge/` に学びとして書く（成功も失敗も資産）。
