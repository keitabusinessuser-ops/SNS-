# cite-gap

> **AIが作り、運営者が確認して公開する。** 設計・実装・テスト・READMEの下書きはAI（Claude）が行い、人が最終確認と公開をします。

文章の中の数字と断定に、**出典か「未確認」の印があるか**を調べるコマンドです。
AIが出した「2割」「3倍」をそのまま載せてしまう失敗を、公開前に拾う補助です。見逃しも誤検出もあります。

**やること:** 印の有無を見る。
**やらないこと:** 数字が正しいかは判定しません。出典があっても正しいとは限りません。

- Python標準ライブラリだけ。依存ゼロ
- 外部に何も送りません。ネットワークを使いません
- 日本語中心（英語は少しだけ）

## 使い方

```
cite-gap draft.md            # 点検する
cite-gap a.md b.txt          # 複数ファイル
cat draft.md | cite-gap -    # 標準入力
cite-gap --json draft.md     # JSONで出す
cite-gap --strict draft.md   # 厳しめ
cite-gap --help
```

インストールせず試すときは、`src` を指定して `python3 -m cite_gap draft.md` でも動きます。

終了コード: ギャップなし `0` / あり `1` / 読み込み・使い方の誤り `2`。公開前のチェックに入れられます。

## 例

入力（`draft.md`、架空の文章）:

```
国内の副業人口は2割に達した。

調査では売上が3倍になった（出典: https://example.com/x 取得日2026-10-01）。

この方法なら必ず稼げる。ただし、これは未確認の仮説です。
```

出力:

```
draft.md:1  出典なし  「国内の副業人口は2割に達した。」  理由: 割合(2割)
-- 数字・断定を含む文 3 件のうち、出典なし 1 件（出典の有無のみを見ています。真偽は判定していません）
```

2文目は出典あり、3文目は「未確認」「仮説」の印があるので、OKです。

## 何を拾うか

| 種類 | 例 |
|---|---|
| 割合 | 50%、2割、3分の1 |
| 倍率 | 3倍 |
| 金額 | 約1,200円、3000万円、$20 |
| 人数・件数 | 1,500人、30社（10未満は除く） |
| 数値 | 12,000（カンマ区切り）。`--strict` では2桁以上の数字すべて |
| 断定 | 必ず、確実、絶対、間違いなく、誰でも、唯一 など |
| 伝聞 | 〜と言われている、〜とされる、〜によると など |

## 何があればOKか

次のどれかが、**同じ文**か**同じ段落**（空行まで。箇条書きは1項目ずつ）にあればOKです。`--strict` は同じ文だけ。

- 出典の印: URL、「出典」「取得日」「引用元」「参考文献」「参考:」、脚注 `[^1]`
- 確かめていない印: 「未確認」「仮説」「要確認」「未検証」

行に `cite-gap: ignore` と書くと、その行は点検しません。

## 誤検出を減らす工夫

見出し、コードブロック、インラインコード、front matter、HTMLコメント、URLの中、日付（2026年10月1日）、時刻、バージョン（v1.2.3）、電話番号、「第3章」を除きます。1人・2人のような小さい人数も統計とみなしません。

## 限界（先に読んでください）

- **誤検出があります。** 体験談の「3倍速かった」も拾います。見出しは見ません。字下げのコードブロックは見分けられません
- **見逃しもあります。** 「かなり多い」のような数字のない主張、期間（3日間）や回数は見ません。漢数字や言い回しの網羅は**未検証**です
- 「参考」「出典」の語があるだけでOKにします。**その出典が本当にその数字を支えているかは見ません。** 出典の取得日が古い、リンクが切れている、も見ません
- 段落の中の1か所に印があれば、同じ段落の他の数字もOKになります。厳しく見たいときは `--strict`
- 英語の検出は少しだけです
- Python 3.13 で動作確認しました。3.9〜3.12 は**未確認**です
- 法的助言ではありません。景品表示法などの観点で問題がないかは、これでは分かりません。専門家に確認してください
